# Visual Design System

## Visual identity

The established visual grammar is:

- Warm cream / off-white page canvas.
- Soft pastel fields: blue, coral/salmon, yellow, lavender, mint, and related muted tones.
- Very dark / near-black condensed display typography.
- Tiny monospaced or technical supporting typography.
- Large rounded geometry.
- Soft sculptural 3D geometric/mechanical artwork.
- Strong negative space.
- Editorial scale rather than dashboard density.

The most important tension is:

**soft environment + hard typography**

## Typography

Use the condensed display type selectively so it retains impact.

Strong places for it:

- `CREATIVE ENGINEER`
- project titles
- `WHAT I BUILD`
- important capability headings
- final contact statement

Do not turn every label and paragraph into display type.

Supporting metadata can use small mono/technical copy such as:

- `SELECTED WORK / 01—03`
- `CAPABILITIES / 01—05`
- `AVAILABLE / 2026`
- `ROLE / DESIGN + ENGINEERING`
- `STACK / NEXT · TYPESCRIPT · POSTGRES`

Do not use fake-terminal language such as `> initializing...`.

## Shape language

Rounded corners are part of the system, but do not place every piece of content inside the same rounded card.

What I Build pills should be thick and substantial. They should feel closer to soft physical bands/capsules than tiny UI chips.

## 3D language

Use 3D artwork as signature graphic material, not mandatory decoration.

Good uses:

- hero sculpture
- selected project art direction
- occasional capability/Lab visual

Avoid:

- adding a sculpture to every card
- generic floating blobs
- humanoid/about-me busts unless the concept genuinely earns it
- 3D purely to fill empty space

## Explicitly rejected patterns

Do not introduce these simply because they are common in modern portfolios:

- grid-heavy/bento layouts
- timelines with lines and circles
- connector diagrams used as decoration
- tiny skill-logo cards
- repeated identical pastel cards
- glassmorphism
- HUD / sci-fi dashboard UI
- fake terminals
- blueprint styling
- generic gears
- excessive particles
- SaaS-dashboard visual language
- conventional `Discover / Design / Build` process cards
- generic About/Process homepage sections

## Design test

Before adding anything, ask:

1. Does this belong to the existing visual world?
2. Is this communicating something, or merely decorating empty space?
3. Does this look like a portfolio template pattern?
4. Would the page still feel distinctive if the 3D artwork were temporarily removed?
5. Is the page becoming too internally repetitive?

Prefer rhythm, scale, whitespace, and composition changes over inventing new styles.
